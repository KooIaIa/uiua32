Completed milestones
1) Core numeric migration
- `Value::Num` is `Array<Num>`.
- `Num = f32` in f32 mode.
- `Complex` uses parser `ComplexNum`, which is also f32 in f32 mode.
- Key algorithm paths are migrated to `Num` in core runtime modules (including GA and dyadic/monadic paths).

2) Full default-feature f32 compile support
- Reintroduced f32-only compatibility bridges in `src/value.rs`:
  - `From<f64> for Value`
  - `From<Array<f64>> for Value`
  - `From<EcoVec<f64>>`, `From<CowSlice<f64>>`, `(Shape, ...)`, array forms, `FromIterator<f64>`
- Purpose: keep optional/default-feature modules (ffi/media/sys/xlsx/constants) compiling without broad churn.

3) Boundary fixes applied for default-feature build
- `src/algorithm/encode.rs`: XLSX cell write uses `f64` cast for `simple_excel_writer`.
- `src/algorithm/media.rs`: removed direct `Value::Num(Array<f64>)` construction; now uses `Into<Value>` conversion.
- `src/algorithm/mod.rs` (FFT): switched to `rustfft` generic `Num` path (`Complex<Num>`, `FftPlanner<Num>`), and Num-typed scaling factor.
- `src/constant.rs`: removed now-redundant f32-only `From<f64> for ConstantValue` impl (conflicted after restoring `From<f64> for Value`).

4) f32-specific Uiua test overrides (default-feature pass)
- Added/updated f32 override tests in `tests_f32/`:
  - `ga.ua`
  - `grid.ua`
  - `optimized.ua`
  - `under.ua`
  - `monadic.ua`
  - `units.ua`
  - `data_defs.ua` (copied for relative import from `units.ua`)
- Purpose: keep baseline f64 tests unchanged while allowing expected f32 precision/format/path differences.

Temporary compatibility still present
1) f64-to-Value bridges in f32 mode (`src/value.rs`)
- These are intentionally temporary compatibility shims for optional/default-feature boundaries.
- They introduce cast boundaries (`f64 -> Num`) but do not change core `Array<Num>` execution type.

2) External format/FFI boundaries
- Some APIs remain naturally f64-oriented (xlsx writer, media decoding helpers, ffi numeric IO).
- These boundaries may still cast through f64 for interoperability.
